# Big Dawg Daily — notes for Claude

Sam's daily puzzle app for his friends. Live at https://samahlersmeyer-prog.github.io/bigdawg/ (GitHub Pages from `main`, installed on iPhones as a home-screen app). Pushing to `main` deploys.

## Working rules (keep token use low)
- Read only the file you need. Use grep to find a function, then read just those lines. Never read whole big files: `js/data.js` (puzzle banks), `strands_x.json`, `offline.html`, `server/Code.gs`.
- `index.html` holds only markup. Logic lives in `js/`, styles in `styles.css`.
- After any change: `python3 tools/stamp.py`, then commit and push. It bumps cache versions so phones update. Never hand-edit `?v=`, `GAMES_V`, or the `V`/`SHELL` lines in `sw.js`.
- Commit messages: short, plain, feature-first (e.g. "Kick Dawg: Pro Range at 1000+").
- Keep this file current: update To-do and anything that changed, and keep it about a page.

## Layout
- `index.html` — markup only, plus the script/style tags (load order matters, see below).
- `styles.css` — all styles (light/dark themes).
- `js/data.js` — puzzle banks: `ANSWERS` (Five), `PUZZLES` (Groups), `MINIS`, `STRANDS`, `VALID` word list. Puzzle of the day = `bank[DAY % length]`, `DAY` counted from `EPOCH` (Oct 6, 2026).
- `js/core.js` — URLs, date/puzzle of the day, local storage, server calls (`API`/`callServer`), toast/modal, navigation (`show(view)`).
- `js/daily.js` — Home and the four daily games (Five, Groups, Mini, Strands), keyboard, results and sharing.
- `js/social.js` — Crews, Week in Review, Scoreboard/standings, Shade (roasts), Big Dawg emotes, confetti/sounds/crown/league/player cards/reactions.
- `js/arcade.js` — Arcade / Sports / Den hubs, built-in Zoomies, Long Dawg, Fetch Breakout, the shared arcade engine, and the `defGameMeta([...])` list of every lazy-loaded game.
- `js/boot.js` — identity ("Who's playing?" + PIN) and `boot()`. With no internet, sign-in still works: the last player list is cached (`bdd:who`), and the claim/register is saved in `bdd:pendme` and finished by `settleMe()` (core.js) before any other server call once online; a wrong PIN or taken name then signs that device out.
- `games/g_*.js` — one file per arcade/sports/den game, lazy-loaded. To add a game: create `games/g_x.js`, add its entry to `defGameMeta` in `js/arcade.js`, and add its key to a section in `ARC_GROUPS`, and add `key: maxScore` to `ARCADE_GAMES` in `server/Code.gs` (without it the server rejects every score and phones drop them; `recoverBests` resends each phone's best once the server knows the game) (Arcade has 4 sections — Retro Classics, Run & Jump, Blast & Battle, Chill & Think — and Sports has 3; unlisted games fall into the last one). When a game ships or gets a real upgrade, add it to `FRESH` in `js/arcade.js` (`key: ["new"|"upd", "YYYY-MM-DD"]`); it shows a NEW/UPDATED tag for 7 days.
- `tools/strands.mjs` — Strands checker/builder. `check` validates every board (no overlaps, no crossing paths, all 48 cells used, theme words 4+ letters, spangram starts on one side and ends on the opposite side — boards already played only had to touch both sides); `stamp.py` runs it and refuses to stamp if any board is broken. `fix` re-lays out broken boards with the same words and rebuilds their bonus words. Add new Strands puzzles as words only and let `fix` make the grid, rather than laying them out by hand. Strands progress is tagged with the board (`S.strands.g`), so changing a live board restarts it for everyone.
- `tools/repeats.mjs` — repeat checker for the four daily puzzles; `stamp.py` refuses to stamp if an upcoming puzzle repeats an earlier one (Five: same word; Groups: same category name or 2+ shared words; Mini: 3+ shared entries; Strands: same title/spangram or 2+ shared words). Only swap upcoming puzzles (bank index > today's `DAY`), never today's or past ones. `node tools/repeats.mjs all` also lists old repeats already played. New puzzles must also be new vs. everything already in the bank.
- `sw.js` — service worker (instant open, quiet background updates). `strands_x.json` — Strands bonus words, fetched after load.
- `legacy/` — generated old-iPad copy (iOS 9 Safari) of the whole app, every game included, at `/bigdawg/legacy/`. Built by `tools/legacy/build.mjs` (run automatically by `stamp.py`; needs Node): Babel to ES5 + polyfills (js/ and games/ → legacy/js/, legacy/games/), CSS grid/gap/clamp rewritten to old flexbox, plus hand fixes in `tools/legacy/shim.js` (pointer→touch without blocking taps on buttons/panels, canvases at 1x for speed, canvas roundRect/ellipse, board sizing; the build also lets the game loop skip up to 1/20 s per frame) and `tools/legacy/legacy.css` (home cards, arcade tiles). Works offline via `legacy/manifest.appcache` (old Application Cache, built with the exact `?v=` URLs; the build fails if a listed file is missing); a new version swaps in on the next open. Never edit `legacy/` by hand. If a new layout looks broken there, fix it in `legacy.css`.
- `offline.html` — generated one-file edition for computers with no internet (Sam's Mac and Dell): double-click to open. Every game, puzzle, font and icon is inlined, and `server/Code.gs` runs inside the page against a pretend Sheet in that browser's localStorage, so players/scores stay on that computer. Built by `tools/offline/build.mjs` (run by `stamp.py`; fonts vendored in `tools/offline/fonts/`). Never edit or read it; fix the build instead. To update a computer's copy, re-download the file (its saved scores stay, since they're keyed to the browser, not the file).
- `server/Code.gs` — Apps Script backend; data in Google Sheet `1VL0FSSHy4VFphMntUA0tKgXBEG4ELWKx7zyXdJvS6Bw`. `server/Loader.gs` is pasted once in Apps Script and pulls `Code.gs` from GitHub, so pushing `Code.gs` goes live in about 10 minutes, no deploy. Server functions are in `API_FNS`.

The `js/` files are classic scripts sharing one global scope, loaded in order data → core → daily → social → arcade → boot. Code that runs at load time can only use things from its own file or earlier files; functions called later (from clicks or `boot()`) can live anywhere.

## The Den
`DEN_SECTIONS` in `js/arcade.js` sets the daily puzzles: Words and Logic, in a fixed order. In Words the first 4 unfinished get big cards and the rest are compact; Logic is all compact. Re-rank that order by hand every month or so from play counts (distinct players per week), not live. NEW games (`FRESH`) pin to the top of their section for 7 days; finished puzzles sink to a slim ✓ row. Den puzzle names are plain (Links, Waffle, Hive, Guess, Sudoku, Pips, Mahjong, Scapes), no "Dawg" prefix, like the core four. Icons are small SVGs in `DEN_ICONS`. Cards show 👑 today's leader and how many played.
- Den Four (the Den's own chill leaderboard): each Den daily ranks the crew today (5 for 1st, 4, 3, 2, then 1 for finishing; ties share), your best 4 count. Strip at the top of The Den (`renderDen4`), board modal (`openDenBoard`: Today / Week = best 5 days / Specialists = each puzzle's week leader), and a line on each Den results card (`den4Note`). Today is worked out on the phone from `arcade.games[k].today`; Week comes from `denFour_` in `Code.gs` (`arcade.den`). Never on the main Scoreboard.
- Scoring rule: every Den daily maxes around 1000 (Sudoku/Pips boards 1000/2000/3000). Word puzzles score on how well you did, never time (Links: 200 per hidden word minus 40 per extra letter shown; Sports Groups: 1000 − 100 per mistake; Waffle, Scapes, Guess, Hive). Crosswords and logic grids (Midi, Sudoku, Pips, Top Dogs, Leash, Bone Ball, Mahjong) are 700 for solving + up to 300 for speed. Changed Nov 11, 2026 (Links/Sports Groups dropped their speed bonus, Mahjong went from 1500 max to 1000).

## Home
The Den sits with the core four, not with Arcade/Sports: `#den-strip` (`renderDenStrip`) under The Mini shows 3 Den icons, x of 13 done and who played; once all four are done it grows into a gold "That's all 4 ✓ Want more?" card. Each core results card ends with its Den look-alike (`DEN_PAIRS`: Five→Waffle/Guess, Groups→Sports Groups/Links, Mini→Midi, Strands→Scapes/Hive; first one not done yet) with a Play button. Home loads the arcade boards ~1 s after boot for this. Under the greeting, `#daybar` chips: done count, streak, and your place today. An unplayed core game shows today's leader (👑 Max · 0:58) instead of its how-to line. The Arcade/Sports buttons only flag brand-new games (first 3 days).

## Arcade / Sports hubs
Top: a slim Game of the Day row (`.gotd`) and a crowns line (games where you hold the all-time top score, from `arcade.games[k].all[0]`). Then the 3-across grid by `ARC_GROUPS` section (Sam didn't like sideways-scrolling shelves): 📌 favorites (press and hold a tile, `bdd:favs:<id>`), Jump back in, then the sections. Tiles show your best, or the blurb if you've never played, plus 👑 the champ. `ARC_PAIRS` folds golf/golf18, putt/putt18 and mjrush/mjzen into one tile that asks which (scores stay separate keys). Dawg Crossing is now Dawgger.

## Den card games
Unlisted Den games (euchre, crib, crazy, sevens, rummy, skipbo, solitaire) fall into the "Card games & more" section. Rummy Dawgs (`g_rummy.js`, Rummikub): 3-round match with traditional plus/minus scoring (out = others' rack totals, jokers 30; dry pool = lowest rack wins the differences); score 300 + match total, +100 for winning (old single-hand scores were converted to old + 200 in the Sheet on Nov 7; phones do the same once via `bdd:rummy2`). Skip-Bo Dawgs (`g_skipbo.js`): vs Rex and Duke, Quick (20) or Classic (30) stockpiles; CPU plays a route to its stockpile card, avoids feeding a pup's stockpile, stacks discards high-to-low; if the deck dries up and everyone passes 3 times, smallest stockpile wins. 7 Up 7 Down (`g_sevens.js`, key `sevens`, added Nov 26, 2026; Sevens/Fan Tan, the game Sam's family plays): vs Rex, Biscuit and Duke, 7♠ opens, must play if you can, else knock; 3 hands, 1 point per card left, low total wins; score 900 − 25 per card + 100 for winning. `seven` is the football game, don't mix them up.

## Retro Classics
Dawg takes on old arcade games. Unfair Dawg (`g_unfair.js`): troll platformer, 5 hand-built levels from a small tile builder (`LV`), 9 lives; every troll is survivable once you know it (e.g. hidden blocks sit where an early jump clears them), so keep that true when adding levels. Its touch controls listen to raw touch events for multi-touch (run + jump at once). Dawgipede (`g_pede.js`): Centipede-style. Cube Dawg (`g_cube.js`): Q*bert-style, 4 level rules x 4 rounds, then repeats faster.

## Mad Dawg (Drive Mad-style)
`g_mad.js`: side-view physics car levels (Run & Jump). Its own small rigid-body engine at the top of the file (no library: polygons/circles, sequential impulses, pin / wheel-suspension / rope joints; meters, y up, 1/120 s steps). 30 levels in `LEVELS`, each built from an op list (`f` flat, `c` curve, `gap`, `br` bridge hinge|crumble, `see`, `el` elevator, `mv` slider, `bx`, `bl`, `wr` wrecking ball, `cr` crusher, `sp` spring, `bo` boost, `ce` ceiling); 8 cars in `CARS`. Head/roof touching ground or a static/moving part = restart. Progress per player in `bdd:mad:<id>`; score = career total (best per level, 1000 + up to 500 vs `PAR`), posted with `G.postQuiet`. When changing physics or levels, check every level is still beatable with a headless bot (load the file in Node `vm` with a `defGame` stub; `GAMEDEFS.mad._t` exposes `build`/`LEVELS`), and reset `PAR` to about 1.1x the bot's times. Keep up-steps under ~0.8x the car's wheel radius and slider platforms longer than the longest car.

## Boomerang Dawgs and Cab Dawg (added Nov 26, 2026)
Both are look-alikes of real games (Boomerang Fu, City Cab Rush): same rules and feel, our own names, characters and art. Keep it that way. Both read raw touch events like Unfair Dawg (two thumbs at once).
- Boomerang Dawgs (`g_boom.js`, Blast & Battle): you vs 3 CPUs on an 11x13 tile arena, 4 maps in `MAPS` (`#` wall, `~` water, `b` bush, `1`-`4` start corners). One-hit KOs; throw (hold to charge, hold empty-handed to recall), slash (also deflects), dash. 14 power-ups in `PW`, 3 held at once, fire/ice don't mix, kept all match. +1 per KO, +1 last standing, first to 10. Score = points x 100, plus 1000 + 150 per point of lead for a win. CPU skill (`s.skill`) rises each round and with your lead; CPUs treat water as a wall. A mode menu opens each match (`MODES`): Free For All, Teams (you + Bao vs Mittens + Rusty, no friendly fire), Golden Boomerang (hold the gold: 1 point per 2.5 s, KOs respawn) and Hide & Seek (teams; hiders have no boomerang and become bushes when still, seekers wait 2.5 s, 30 s rounds, +2 per find / per survivor, sides swap). Points are per team in `s.tp`. Six more power-ups (ghost dash, telekinesis, decoy, disguise, battle royale = closing rings in `s.storm`, bamboozled); all four modes share the one `boom` leaderboard.
- Cab Dawg (`g_cab.js`, Run & Jump): 8x8-block city (`CITY`, same every run), camera turns with the cab, buildings drawn leaning for the 3D look (`pt`). 5 timed days; stop rings auto-brake the cab; riders have a timer (tip for speed, bumps cut it, traffic hit = -2 s); shop between days (`UPS`). Score = total dollars earned. Touch: hold a side to steer, gas is automatic, both sides = brake/reverse.
- Check either with a headless run (load the file in Node `vm` with `defGame`/`G` stubs and a fake canvas, play whole matches/weeks with a simple bot) after changing rules or CPU behavior.

## Hook Dawg (Stickman Hook-style)
`g_hook.js`: 24 swing levels instead of the old endless run (Nov 26, 2026): grab only inside a hook's dashed ring, rope reels in (adds speed), round bumpers, striped solid blocks, checkered finish, fall = instant restart. Score = career total like Mad Dawg (best per level, 1000 + up to 500 vs `PAR`), progress in `bdd:hook:<id>`. Levels and `PAR` come from `node tools/hook.mjs gen` (seeded generator + hook-to-hook bot, sorted easiest first); `node tools/hook.mjs` re-checks every level is beatable, so run it after any physics change.
- Other Poki look-alikes brought closer on Nov 26, 2026. Dawg Dash (`g_dash.js`, Subway Surfers): red moving trains (`spawnMover` picks a lane that isn't any nearby row's open lane and has no parked train), sideswipe = stumble with the dogcatcher close (second stumble inside 6 s = caught), 🚀 rocket and 👟 spring shoes. Blumji Bounce (`g_blumji.js`, Blumgi Slime): 20 stages, spike platforms (type `"s"`) and solid walls (`w`); `node tools/blumji.mjs` finds the fewest hops per stage, so run it when adding stages and set `par` from it. Pup Shot (`g_pupshot.js`, Blumgi Ball): 20 courts, the new ones use pink pads, bombs and magnets; `node tools/pupshot.mjs` does the same for courts (slow, about 10 minutes).
- Not changed: Dawg Lords and Mad Dawg. No trustworthy description of Top Lords was found to compare against, and Mad Dawg already follows Drive Mad; change them only from specific notes from Sam.

## Feud (temp: Thanksgiving weekend, Nov 26-29, 2026)
`g_feud.js`: Family Feud-style Den daily, 5 questions a day, typed guesses, 3 strikes a question, 200 per question = your share of the board's points. Thu-Sat boards (`DAYS`) are real published polls, source shown under each question, points = the poll's percent (the one ranked-only list says so in its source line). Only add questions with a real source. Guess matching is loose (`norm`/`alike`: plurals, -ing, typos, whole-word pieces; 2+ possible answers = "be more specific"), so give each answer its common aliases. Sunday is the Crew Edition: the Home banner (`#feud-survey`, `FEUD_QS` / `openFeudSurvey` in `js/arcade.js`) collects 5 answers per player into the `FeudSurvey` tab (`sendFeudSurvey`), answers stay on the server until Sunday (`FEUD_CLOSE`), then `getFeudSurvey` returns them without names and each phone groups them into the board (`crewBoard`). Under 3 crew answers = the `SPARE` poll board. Host mode (Solo | Host switch at the top, added Nov 26): one screen for the room, two teams, a pot, Strike with the big red X and buzzer, last round triple and the one before double; the host flips answers by tapping with Peek on or by typing what a player said (same matcher). Decks: Party mix (5 rounds: three Thursday poll boards with two crew questions between them, the default for a room), the crew's answers so far, or every poll board already out. A failed TV push retries (5 tries, 2 s apart), and a new game keeps the phone's TV code (`bdd:feud:code`) so the TV follows without retyping. One game at a time in `bdd:feud:host`; it never posts a score. TV link: starting a host game calls `feudHost` for a 4-letter TV code; the phone pushes only what the room may see (`view()` → `feudPush`, flipped answers only) and a second device in TV mode (`tvOpen`, the `.ftv` full-screen board in styles.css) polls `feudWatch(code)` about every second. Game state is in the Apps Script cache only (6 h), never the Sheet. Crew answers are locked: before Sunday they only come down through `feudHost(id, "crew")` to that host's phone, and each such start is logged in the `FeudHosts` tab. The offline edition has no shared cache, so the TV link needs the live site. `FEUD_ON` (`KEY <= FEUD_END`) keeps the game out of the app after Sunday. `node` test idea: load the file in `vm` with a `defGame` stub; `GAMEDEFS.feud._t` exposes `match`/`crewBoard`/`DAYS`.

## Skills (check these first)
This repo ships skills in `.claude/skills/` (brainstorming executing-plans impeccable ponytail ponytail-audit ponytail-review security-audit systematic-debugging verification-before-completion writing-plans ). Before starting a task, check which apply, read that SKILL.md, and follow it.
- **ponytail** — every coding task: smallest change that fully works; reuse what's already here. `ponytail-review` / `ponytail-audit` to trim bloat.
- **brainstorming → writing-plans → executing-plans** — new features or anything bigger than a quick fix.
- **systematic-debugging** — any bug: find the root cause before changing code.
- **verification-before-completion** — test it before calling it done.
- **impeccable** — any UI work: new screens, polish, `/impeccable audit`. Prefer it over frontend-design.
- **security-audit** — before handing the app to anyone, before launches, and after adding logins, firestore.rules, Apps Script endpoints or anything storing people's data. This repo only.
