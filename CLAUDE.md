# Big Dawg Daily — notes for Claude

Sam's daily puzzle app for his friends. Live at https://samahlersmeyer-prog.github.io/bigdawg/ (GitHub Pages from `main`, installed on iPhones as a home-screen app). Pushing to `main` deploys.

## Working rules (keep token use low)
- Read only the file you need. Use grep to find a function, then read just those lines. Never read whole big files: `js/data.js` (puzzle banks), `strands_x.json`, `offline.html`, `server/Code.gs`.
- `index.html` holds only markup. Logic lives in `js/`, styles in `styles.css`.
- After any change: `python3 tools/stamp.py`, then commit and push. It bumps cache versions so phones update. Never hand-edit `?v=`, `GAMES_V`, or the `V`/`SHELL` lines in `sw.js`.
- Commit messages: short, plain, feature-first (e.g. "Kick Dawg: Pro Range at 1000+").
- Keep this file current: update To-do and anything that changed, and keep it about a page.

## Layout
- `index.html` — markup only, plus the script/style tags (load order matters, see below).
- `styles.css` — all styles (light/dark themes).
- `js/data.js` — puzzle banks: `ANSWERS` (Five), `PUZZLES` (Groups), `MINIS`, `STRANDS`, `VALID` word list. Puzzle of the day = `bank[DAY % length]`, `DAY` counted from `EPOCH` (Oct 6, 2026).
- `js/core.js` — URLs, date/puzzle of the day, local storage, server calls (`API`/`callServer`), toast/modal, navigation (`show(view)`).
- `js/daily.js` — Home and the four daily games (Five, Groups, Mini, Strands), keyboard, results and sharing.
- `js/social.js` — Crews, Week in Review, Scoreboard/standings, Shade (roasts), Big Dawg emotes, confetti/sounds/crown/league/player cards/reactions.
- `js/arcade.js` — Arcade / Sports / Den hubs, built-in Zoomies, Long Dawg, Fetch Breakout, the shared arcade engine, and the `defGameMeta([...])` list of every lazy-loaded game.
- `js/boot.js` — identity ("Who's playing?" + PIN) and `boot()`. With no internet, sign-in still works: the last player list is cached (`bdd:who`), and the claim/register is saved in `bdd:pendme` and finished by `settleMe()` (core.js) before any other server call once online; a wrong PIN or taken name then signs that device out.
- `games/g_*.js` — one file per arcade/sports/den game, lazy-loaded. To add a game: create `games/g_x.js`, add its entry to `defGameMeta` in `js/arcade.js`, and add its key to a section in `ARC_GROUPS`, and add `key: maxScore` to `ARCADE_GAMES` in `server/Code.gs` (without it the server rejects every score and phones drop them; `recoverBests` resends each phone's best once the server knows the game) (Arcade has 4 sections — Retro Classics, Run & Jump, Blast & Battle, Chill & Think — and Sports has 3; unlisted games fall into the last one). When a game ships or gets a real upgrade, add it to `FRESH` in `js/arcade.js` (`key: ["new"|"upd", "YYYY-MM-DD"]`); it shows a NEW/UPDATED tag for 7 days.
- `tools/strands.mjs` — Strands checker/builder. `check` validates every board (no overlaps, no crossing paths, all 48 cells used, theme words 4+ letters, spangram starts on one side and ends on the opposite side — boards already played only had to touch both sides); `stamp.py` runs it and refuses to stamp if any board is broken. `fix` re-lays out broken boards with the same words and rebuilds their bonus words. Add new Strands puzzles as words only and let `fix` make the grid, rather than laying them out by hand. Strands progress is tagged with the board (`S.strands.g`), so changing a live board restarts it for everyone.
- `tools/repeats.mjs` — repeat checker for the four daily puzzles; `stamp.py` refuses to stamp if an upcoming puzzle repeats an earlier one (Five: same word; Groups: same category name or 2+ shared words; Mini: 3+ shared entries; Strands: same title/spangram or 2+ shared words). Only swap upcoming puzzles (bank index > today's `DAY`), never today's or past ones. `node tools/repeats.mjs all` also lists old repeats already played. New puzzles must also be new vs. everything already in the bank.
- `sw.js` — service worker (instant open, quiet background updates). `strands_x.json` — Strands bonus words, fetched after load.
- `legacy/` — generated old-iPad copy (iOS 9 Safari) of the whole app, every game included, at `/bigdawg/legacy/`. Built by `tools/legacy/build.mjs` (run automatically by `stamp.py`; needs Node): Babel to ES5 + polyfills (js/ and games/ → legacy/js/, legacy/games/), CSS grid/gap/clamp rewritten to old flexbox, plus hand fixes in `tools/legacy/shim.js` (pointer→touch without blocking taps on buttons/panels, canvases at 1x for speed, canvas roundRect/ellipse, board sizing; the build also lets the game loop skip up to 1/20 s per frame) and `tools/legacy/legacy.css` (home cards, arcade tiles). Works offline via `legacy/manifest.appcache` (old Application Cache, built with the exact `?v=` URLs; the build fails if a listed file is missing); a new version swaps in on the next open. Never edit `legacy/` by hand. If a new layout looks broken there, fix it in `legacy.css`.
- `offline.html` — generated one-file edition for computers with no internet (Sam's Mac and Dell): double-click to open. Every game, puzzle, font and icon is inlined, and `server/Code.gs` runs inside the page against a pretend Sheet in that browser's localStorage, so players/scores stay on that computer. Built by `tools/offline/build.mjs` (run by `stamp.py`; fonts vendored in `tools/offline/fonts/`). Never edit or read it; fix the build instead. To update a computer's copy, re-download the file (its saved scores stay, since they're keyed to the browser, not the file).
- `server/Code.gs` — Apps Script backend; data in Google Sheet `1VL0FSSHy4VFphMntUA0tKgXBEG4ELWKx7zyXdJvS6Bw`. `server/Loader.gs` is pasted once in Apps Script and pulls `Code.gs` from GitHub, so pushing `Code.gs` goes live in about 10 minutes, no deploy. Server functions are in `API_FNS`.

The `js/` files are classic scripts sharing one global scope, loaded in order data → core → daily → social → arcade → boot. Code that runs at load time can only use things from its own file or earlier files; functions called later (from clicks or `boot()`) can live anywhere.

## The Den
`DEN_SECTIONS` in `js/arcade.js` sets the daily puzzles: Words and Logic, in a fixed order. In Words the first 4 unfinished get big cards and the rest are compact; Logic is all compact. Re-rank that order by hand every month or so from play counts (distinct players per week), not live. NEW games (`FRESH`) pin to the top of their section for 7 days; finished puzzles sink to a slim ✓ row. Den puzzle names are plain (Links, Waffle, Hive, Guess, Sudoku, Pips, Mahjong, Scapes), no "Dawg" prefix, like the core four. Icons are small SVGs in `DEN_ICONS`. Cards show 👑 today's leader and how many played.
- Den Four (the Den's own chill leaderboard): each Den daily ranks the crew today (5 for 1st, 4, 3, 2, then 1 for finishing; ties share), your best 4 count. Strip at the top of The Den (`renderDen4`), board modal (`openDenBoard`: Today / Week = best 5 days / Specialists = each puzzle's week leader), and a line on each Den results card (`den4Note`). Today is worked out on the phone from `arcade.games[k].today`; Week comes from `denFour_` in `Code.gs` (`arcade.den`). Never on the main Scoreboard.
- Scoring rule: every Den daily maxes around 1000 (Sudoku/Pips boards 1000/2000/3000). Word puzzles score on how well you did, never time (Links: 200 per hidden word minus 40 per extra letter shown; Sports Groups: 1000 − 100 per mistake; Waffle, Scapes, Guess, Hive). Crosswords and logic grids (Midi, Sudoku, Pips, Top Dogs, Leash, Bone Ball, Mahjong) are 700 for solving + up to 300 for speed. Changed Nov 11, 2026 (Links/Sports Groups dropped their speed bonus, Mahjong went from 1500 max to 1000).

## Home
Under the greeting, `#daybar` chips: done count, streak, and your place today. An unplayed core game shows today's leader (👑 Max · 0:58) instead of its how-to line. The hub buttons only flag brand-new games (first 3 days); The Den's button shows "x of 13 done today".

## Den card games
Unlisted Den games (euchre, crib, crazy, rummy, skipbo, solitaire) fall into the "Card games & more" section. Rummy Dawgs (`g_rummy.js`, Rummikub): 3-round match with traditional plus/minus scoring (out = others' rack totals, jokers 30; dry pool = lowest rack wins the differences); score 300 + match total, +100 for winning (old single-hand scores were converted to old + 200 in the Sheet on Nov 7; phones do the same once via `bdd:rummy2`). Skip-Bo Dawgs (`g_skipbo.js`): vs Rex and Duke, Quick (20) or Classic (30) stockpiles; CPU plays a route to its stockpile card, avoids feeding a pup's stockpile, stacks discards high-to-low; if the deck dries up and everyone passes 3 times, smallest stockpile wins.

## Retro Classics
Dawg takes on old arcade games. Unfair Dawg (`g_unfair.js`): troll platformer, 5 hand-built levels from a small tile builder (`LV`), 9 lives; every troll is survivable once you know it (e.g. hidden blocks sit where an early jump clears them), so keep that true when adding levels. Its touch controls listen to raw touch events for multi-touch (run + jump at once). Dawgipede (`g_pede.js`): Centipede-style. Cube Dawg (`g_cube.js`): Q*bert-style, 4 level rules x 4 rounds, then repeats faster.
